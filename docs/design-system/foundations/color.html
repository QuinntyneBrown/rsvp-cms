Color

One blue accent, a gray interface and four status hues, defined once as primitives and given meaning as semantic tokens that both themes override.

Overview

Invitely's colour is a calm gray canvas, white or near-black surfaces, one blue accent for action and selection, and four status hues that always travel with an icon and words. Every value was harvested from docs/mocks/assets/tokens.css; the mocks used the values verbatim, so nothing in the product looks different after extraction.

  • Primitives (--palette-*) are raw hex values. Only semantic tokens read them.
  • Semantic tokens (--color-*) say what a colour is for. Components and pages read only these, and the dark theme overrides only these.
  • 53 primitives, 53 semantic colour tokens, 75 checked contrast pairs, all passing WCAG 2.2 AA in both themes.

Primitive ramps

Five ramps. Gray carries the interface; blue is the accent and the info status; green, amber and red are statuses only. Steps are numbered by lightness, 25 (lightest) to 950 (darkest).

Accent and focus

The accent is blue-600 in light and blue-300 in dark. It marks the one primary action on a view, selected and current states (current nav link, selected tab, pressed chip, current page), checked controls, progress and the focus ring. Text on the accent is --color-fg-on-accent: white in light, blue-950 in dark, because a pale accent needs dark text.

Status colours

Each status has five roles: bg (alert and badge fill), fg (text on that fill and on surfaces), border (decorative alert edge), icon (meaningful icon, 3:1) and solid (filled marks such as the danger button, solid badges, the success progress bar). Toasts sit on the inverse surface, so they use --color-*-icon-on-inverse, added during extraction because the regular icon colours fell below 3:1 on the light inverse surface of the dark theme.

Both themes

Light is the default on :root and on any [data-theme="light"] element; dark applies on [data-theme="dark"] and automatically when the OS prefers dark unless the page forces light. Dark is built from roles, not by inverting light:

  • Surfaces step up in lightness as they rise: canvas gray-950, surface gray-900, raised gray-800, sunken gray-925 (below the canvas's neighbour).
  • The accent and statuses move to their 300 steps; text on solid fills flips to the 950 step.
  • Status backgrounds become deep 950 tints with 200/300 text.
  • Borders: default gray-750 (decorative), strong gray-450 (controls, 3:1 on raised gray-800).

Adding a brand theme

A brand or partner theme is one more block that overrides semantic tokens only. Add primitives for the new hue, map the accent roles, then add every new pairing to contrast-pairs.json and run the checker.

/* tokens.css */
:root { --palette-plum-600: #7b3fa0; --palette-plum-700: #65308a; --palette-plum-50: #f5eefa; }
[data-theme="plum"] {
  --color-accent: var(--palette-plum-600);
  --color-accent-hover: var(--palette-plum-700);
  --color-accent-subtle: var(--palette-plum-50);
  --color-fg-accent: var(--palette-plum-700);
  --color-focus-ring: var(--palette-plum-600);
}
python .claude/skills/extracting-design-systems/scripts/check_contrast.py docs/design-system/tokens/tokens.css

The checker reads every [data-theme] block, so the new theme is checked against every pair automatically. A theme needs its own dark variant if it is offered in dark mode.

Usage

  • Components read semantic tokens; never --palette-*, never a hex value. check_design_system.py rejects raw colours outside tokens/.
  • One accent. Blue means “you can act here” or “this is selected”; it never decorates.
  • Status colour is never alone: badges carry a dot and a word (“Bounced”), alerts an icon and a title, field errors a ⚠ and a sentence (1.4.1).
  • Danger red appears on destructive confirmations, errors and bounced or failed counts only, never for emphasis.
  • Use --color-fg-muted for secondary text; reach for --color-fg-subtle only for placeholders, counters and sidebar group labels.
  • --color-bg-backdrop is translucent (55% in light, 65% in dark) and only sits behind a modal.

Accessibility

WCAG 2.2 AA in both themes: text ≥ 4.5:1 (1.4.3), meaningful non-text ≥ 3:1 (1.4.11), colour never the only signal (1.4.1). Under prefers-contrast: more default borders become strong and muted text becomes default. Under forced-colors: active the focus ring becomes Highlight and borders CanvasText, and components add explicit borders so shapes survive.
