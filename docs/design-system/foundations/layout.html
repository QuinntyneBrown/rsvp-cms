Layout

Mobile first, five breakpoints, a 4/8/12-column grid whose gutters and margins are tokens, and four page templates that cover every mock.

Overview

Layout in Invitely is four page templates on a mobile-first grid. Columns, gutters and margins are tokens that change at two breakpoints, so components inherit the right spacing for the screen instead of writing their own media queries.

Breakpoints

Mobile first: base styles target a 360px phone and min-width queries add room. Queries are written in rem (40rem, 48rem, 64rem) so they move with the reader's font size. Custom properties cannot be used inside @media, so the values are repeated there by convention; the tokens document them. There are no max-width queries in the system.

Columns, gutters and margins

Margin is the space from the viewport edge to content; gutter is the space between columns. tokens.css updates --layout-columns, --layout-gutter and --layout-margin at md and lg, so .grid, .container and the top bar follow without media queries of their own. Page templates

Every mock is one of four page templates. Pick the template first; the components follow.

Layout primitives

The layout primitives (.container, .stack, .cluster, .grid, .split) are documented as a component: Layout primitives. Their rules:

  • Content never touches the viewport edge: .container pads by --layout-margin.
  • One column below md for forms; two only for short related fields (date and start time, first and last name) via .form-row.
  • Sections sit --space-8 to --space-12 apart; cards in a grid sit one gutter apart.
  • Full-height layouts use 100dvh, so mobile browser chrome does not clip them; fixed bottom elements add env(safe-area-inset-bottom).

Usage

  • Use min-width queries in rem, at the documented breakpoints only. A component that needs a query outside them is a sign it should read a layout token instead.
  • Let auto-fill grids choose column counts for cards; reserve .grid with explicit spans for true column layouts.
  • No horizontal page scroll at 320px CSS width. Tables scroll inside .table-wrap; tabs scroll inside .tabs.
  • Keep page-local layout CSS out of mocks and pages. The CMS editor's .cms-grid was copied into ten mocks as a <style> block; it is now .split.

Accessibility

  • Reflow (1.4.10): every template works at 320px wide and at 400% zoom without two-dimensional scrolling, except data tables.
  • Landmarks: each template has one <main id="main">, a labelled <nav> per navigation and a <header> top bar; the skip link targets #main.
  • DOM order equals visual order in every template; the sidebar comes before main in the source, as it does on screen.
  • Sticky top bar never hides focus (2.4.11): scroll-padding-top is the top-bar height plus 16px.
