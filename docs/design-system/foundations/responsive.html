Overview

Invitely is designed at 360px first. Base styles are the phone layout; breakpoints only add room: more columns, wider gutters, a permanent sidebar. Organisers often check replies on a phone and guests almost always RSVP on one, so nothing may need a desktop to work.

  • Mobile first: write base styles for phones, then @media (min-width: …rem). The system uses no max-width queries.
  • Breakpoints in rem so they move with the reader's font size.
  • Components read --layout-columns, --layout-gutter and --layout-margin, which tokens.css updates at md and lg, instead of writing their own queries where possible.
  • No horizontal page scroll from 320px to 1920px (L2-080); only wide tables scroll, inside their wrapper (L2-081).

Columns, gutters and margins

Margin is the space from the viewport edge to content; gutter is the space between columns. Both grow at md and lg. The live grid and container rules are on the layout page.

  • Grid: repeat(var(--layout-columns), minmax(0, 1fr)) with gap: var(--layout-gutter).
  • Card grids: .grid--auto (minmax(18rem, 1fr)); stat rows: .grid--stats (minmax(10rem, 1fr)).
  • Containers: organiser pages cap at 80rem (--layout-container-max); the guest page uses 42rem (--layout-container-narrow) below 62rem and 60rem (--layout-container-guest) from 62rem; the RSVP form is at most 45rem (--layout-form-max); auth cards are 26rem.

Type and spacing

  • Type uses fixed steps from the scale, not viewport units, so zoom works. Body text stays 16px on every screen.
  • Headings do not shrink on phones; long event names wrap (text-wrap: balance) rather than truncate.
  • Spacing never scales with viewport width; the breakpoint swaps the token (gutter 16 → 24 → 32px).
  • Prose is capped at --layout-measure (65ch) at every width.

Touch and pointer

  • Under (pointer: coarse) every button, link and control has a hit area of at least 44×44px (--target-comfortable, L2-084); with a fine pointer the floor is 24px. See target sizes.
  • (hover: none) reveals hover-only affordances permanently: table row actions are always visible on touch screens (L2-084).
  • Grow the hit area, not the drawing: a 32px icon button keeps its look and gains invisible padding to 44px under a coarse pointer.
  • Fixed bottom elements (toasts, sheet footers) respect env(safe-area-inset-bottom).
  • Full-height layouts use 100dvh so mobile browser bars do not clip the sheet or the sidebar.
  • Drag is never the only way: CMS blocks reorder with Move up and Move down; the CSV drop zone has a Choose file button.

Usage

Accessibility

  • Reflow (WCAG 1.4.10): every page works at 320px CSS width, which is 1280px at 400% zoom, with no two-dimensional scrolling except data tables.
  • Resize text (1.4.4): all sizes are rem, so 200% text zoom grows layouts without clipping; breakpoints in rem switch layouts earlier as text grows.
  • Orientation (1.3.4): nothing locks to portrait or landscape.
  • Focus not obscured (2.4.11): the sticky top bar is matched by scroll-padding-top, and toasts never cover a focused control.
  • Text spacing (1.4.12): no fixed heights on text containers, so 1.5 line height and wider letter spacing do not clip.
