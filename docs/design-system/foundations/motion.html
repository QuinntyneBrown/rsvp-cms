Motion

Motion explains what changed and where it went. It is brief, it never blocks input, and it steps aside when someone asks for less.

Overview

Motion in Invitely explains change: a dialog arrives from where attention is going, a toast slides up into the corner it will live in, a switch thumb travels to its new side. It is short, it never blocks input, and it disappears when someone asks for less motion. Every duration and curve is a token, so components never write a raw time.

  • Hover and press feedback: --duration-fast (120 ms).
  • Every overlay entrance (dialog, sheet, drawer, toast, banner) and short reveals: --duration-base (200 ms), the single entrance token required by L2-089.
  • Progress that fills over time: --duration-slow (320 ms).
  • Loops that report status (spinner, shimmer, pulse) have their own tokens and their own reduced-motion rule.

Loops and delays

Loops are not transitions: they repeat until the work ends, and they report status rather than decorate. They have their own tokens so changing hover speed never changes how fast a spinner turns.

How the pieces move together in the mocks' flows:

  • One thing moves at a time. When a dialog closes and a toast appears, the toast starts after the panel has gone.
  • Nothing moves farther than it needs to: 1px for a press, 16px for a toast, never the full viewport.
  • Motion never delays input: buttons in an entering dialog work the moment they are visible.
  • Page navigation does not animate; Invitely pages load in place.

Usage

  • Reference tokens in CSS: transition: background-color var(--duration-fast) var(--ease-standard);. Never write 200ms or ease-in-out in a component.
  • Transition only the properties that change (background-color, border-color, translate, opacity). Never transition: all.
  • Animate opacity, translate and scale; avoid animating height or width except the progress bar.
  • Use --ease-enter for arrival and --ease-exit for departure, never the other way round.
  • No autoplaying motion other than the status loops. Nothing in Invitely parallaxes, bounces on load or animates on scroll.

Accessibility

Requirement L2-089. With prefers-reduced-motion set, a toast, dialog or banner appears without slide or fade, and reordering CMS blocks is immediate. Because every overlay entrance uses --duration-base, one token change satisfies both criteria.

Reduced motion is handled by the tokens. Under prefers-reduced-motion: reduce, tokens.css sets --duration-fast, --duration-base, --duration-slow and --duration-deliberate to 0.01ms, so every component that uses them stops animating without its own media query. components.css adds one safety net that forces any remaining animation to a single, near-instant iteration.

  • Spinners slow down instead of stopping (to three times --duration-spin): a frozen spinner reads as a hung page.
  • Skeletons stop shimmering and become flat placeholders; the container's aria-busy still announces loading.
  • Indeterminate progress becomes a full, 60% opaque bar.
  • Smooth scrolling to anchors becomes an instant jump.
  • No animation flashes more than three times a second (WCAG 2.3.1); the pulse dot cycles once every 1.6 s.
  • Motion never carries meaning on its own: a toast's arrival is also announced by its live region.

Test with the OS setting (Windows: Settings → Accessibility → Visual effects → Animation effects off) or DevTools → Rendering → Emulate prefers-reduced-motion. The resolved values in the tables on this page change live when you do.
