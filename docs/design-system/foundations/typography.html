Typography

A system sans for every word, mono for invitation codes, and twelve role tokens that set weight, size, line height and family in one declaration.

Overview

One sans family for everything, one mono family for codes, nine sizes on a gentle modular scale and twelve role shorthands. Components set type with a role (font: var(--text-label)), never with loose sizes and weights, so a role change ripples everywhere at once.

  • Body text is 16px (--font-size-md) and never smaller on inputs, so iOS does not zoom on focus.
  • Nothing is smaller than 12px (--font-size-xs).
  • Headings use tighter line heights (1.2–1.3) and a slight negative tracking; body uses 1.5.
  • All sizes are in rem, so the whole scale follows the reader's browser font size (1.4.4).

Families

Inter is named first, but no mock loads it: there is no @font-face or font link anywhere in docs/mocks, so the mocks and these pages render in the system UI font (Segoe UI on Windows, San Francisco on Apple, Roboto on Android) unless Inter is installed locally. The product should either self-host Inter (variable, latin subset, font-display: swap) or accept the system stack; the scale works with both.

Usage

  • Set type with a role token: font: var(--text-body-sm). Override a single property (colour, font-variant-numeric) after it, never the size.
  • One <h1> per page; skip no levels. Visual size follows the role, not the element: a card title is an <h2> with .card__title (h4 size).
  • Measure: paragraphs cap at --layout-measure (65ch); empty-state text at 36ch.
  • Numbers that change or line up (stats, counts, table columns, pagination) use font-variant-numeric: tabular-nums.
  • Headings and short centred text use text-wrap: balance; paragraphs use text-wrap: pretty.
  • Sentence case everywhere, including buttons and headings; uppercase only through .overline and badges.

Responsive type

Type does not scale with the viewport. Sizes are fixed steps in rem that respect user zoom; on phones the public headline stays h1 (36px) and wraps, balanced. If a display headline is ever needed it may use clamp(2.25rem, 1.5rem + 2vw, 3rem), documented where used.

Accessibility

  • Text sizes are in rem and layouts reflow at 200% and 400% zoom (1.4.4, 1.4.10).
  • Nothing breaks with 1.5× line height, 2× paragraph spacing, 0.12em letter and 0.16em word spacing (1.4.12): no fixed heights on text containers.
  • Body text contrast is at least 4.5:1 on every surface (see contrast pairs); muted and subtle text pass too.
  • Uppercase is styling, not content: the HTML says “Birthday · Sat 14 Nov 2026” so screen readers do not spell it out.
  • Headings form an outline that matches the visual hierarchy (2.4.6, 1.3.1).
