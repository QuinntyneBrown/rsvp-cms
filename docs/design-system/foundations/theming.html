Theming

One set of tokens, two themes. A theme only overrides semantic tokens, so every component works in light, dark, high contrast and forced colours without knowing which it is in.

Overview

Invitely ships a light and a dark theme from one set of tokens. A theme is nothing more than a block of semantic-token overrides: components never know which theme they are in, and nothing outside tokens/tokens.css contains a colour. The dark theme overrides 57 semantic tokens; everything else (type, space, shape, motion, layout) is shared.

  • Light is the default (:root).
  • Dark follows the operating system unless a page forces light, or applies anywhere with data-theme="dark".
  • High contrast and forced colours adjust the same tokens, not the components.

Token tiers

1 · Primitive--palette-blue-600: #2563ebRaw values. Named for what they are. Only semantic tokens read them.
2 · Semantic--color-accent: var(--palette-blue-600)Named for what they mean. Components read these; themes override only this tier.
3 · Component--btn-bg: var(--color-accent)Scoped to one component in components.css. Re-skins override these.

A value appears once as a primitive, gains meaning as a semantic token, and is scoped as a component token. Changing the brand hue touches primitives; changing what “accent” means touches semantics; changing how buttons look touches component tokens. The 214 tokens in tokens.css are browsable on the color, typography, spacing, layout, elevation, shape, motion and accessibility pages.

How themes apply

/* tokens.css */
:root,
[data-theme="light"] { /* primitives + light semantic tokens */ color-scheme: light; }
[data-theme="dark"]  { /* dark semantic overrides */          color-scheme: dark; }
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { /* the same dark overrides */ }
}
  • Follow the OS: with no attribute, a dark OS preference applies the dark block to :root.
  • Force a theme: <html data-theme="dark"> or data-theme="light"; this is how a saved choice is applied (see the resolution order below).
  • Scope a theme: any element can carry data-theme; its descendants resolve that theme. This documentation uses it for the side-by-side frames.
  • color-scheme is set in each block so native controls, date pickers and scrollbars match.
  • The two dark blocks must stay identical; check_contrast.py reads both.

Which theme wins (L2-088)

  1. A saved choice. When the organiser picks Light or Dark in the theme control, the choice is written to localStorage and applied as data-theme on <html> by an inline script before first paint, so the next visit opens in that theme with no flash.
  2. The operating system. With no saved choice, a dark OS preference gives the dark theme (the prefers-color-scheme block).
  3. Light. With no saved choice and no preference, the page is light.

If localStorage is unavailable (private mode, blocked storage), changing the theme still applies data-theme for the current page only, and no error is shown. Wrap every storage read and write in try/catch.

<script>
  try {
    var saved = localStorage.getItem("invitely-theme");
    if (saved === "light" || saved === "dark") document.documentElement.dataset.theme = saved;
  } catch (e) { /* no storage: fall through to the OS preference */ }
</script>

The mocks do not show the theme control yet (the theme buttons in them belong to the mock bar), so its placement is still to be designed; the account page is the natural home.

Fix made during extraction: the mocks' tokens.css declared light values on :root only, so a [data-theme="light"] frame inside a dark page inherited dark tokens and rendered dark. The light block is now also scoped to [data-theme="light"], which makes nested light frames (and a forced-light page on a dark OS) resolve correctly.

Contrast and forced colours

PreferenceWhat changes
prefers-contrast: moreDecorative dividers take the strong border colour; muted and subtle text take the default text colour.
forced-colors: activeFocus ring becomes Highlight, borders become CanvasText; buttons, inputs, cards, chips, badges, alerts and toasts draw a system-colour border, the primary button uses Highlight, and current nav links and tabs get a Highlight outline.
prefers-reduced-motion: reduceDurations collapse to near zero; see motion.

Adding a theme

  1. Copy the [data-theme="dark"] block and rename it ([data-theme="partner"]).
  2. Override semantic tokens only. Add primitives for new hues at the top of :root; never put a raw colour in a semantic token.
  3. Set color-scheme to the theme's base (light or dark).
  4. Run python check_contrast.py docs/design-system/tokens/tokens.css; every pair in contrast-pairs.json is checked in the new theme too. Fix primitives until it exits 0.
  5. Run python tokens_to_json.py docs/design-system/tokens/tokens.css so tokens.json carries the new overrides.
  6. Screenshot a component page inside <div data-theme="partner"> and check surfaces read as raised.
[data-theme="partner"] {
  --palette-teal-600: #0f766e;            /* new primitive (or add it to :root) */
  --color-accent: var(--palette-teal-600);
  --color-accent-hover: var(--palette-teal-700);
  --color-fg-link: var(--palette-teal-700);
  --color-focus-ring: var(--palette-teal-600);
  color-scheme: light;
}

Consuming tokens.json

tokens/tokens.json is generated from tokens.css in the W3C Design Tokens (DTCG) format: --color-accent becomes color.accent, aliases stay aliases, and theme overrides sit under $extensions. This is the real entry for the accent:

"color": {
  "accent": {
    "$type": "color",
    "$value": "{palette.blue.600}",
    "$extensions": {
      "com.agent-toolkit": {
        "css": "--color-accent",
        "resolved": "#2563eb",
        "themes": {
          "dark": {
            "$value": "{palette.blue.300}",
            "resolved": "#8ab4ff"
          }
        }
      }
    }
  },
  …
}

The React apps do not need it: components read CSS custom properties from src/shared/ui/tokens.css, which mirrors these values (code in src/ never imports from docs/). Use the JSON for anything that cannot read CSS: e-mail templates (which need resolved hex values), charts, native wrappers or a Figma sync.

import tokens from "./tokens.json";

// Resolved light value, and the dark override when there is one
const accent = tokens.color.accent.$extensions["com.agent-toolkit"];
const light = accent.resolved;                  // "#2563eb"
const dark = accent.themes?.dark?.resolved;     // "#8ab4ff"

Usage

  • Do not test a theme by eye alone: run the contrast check.
  • Never read the saved theme on the server: apply it from localStorage before first paint (L2-088).

Accessibility

Both themes pass WCAG 2.2 AA for every pair listed in tokens/contrast-pairs.json (79 pairs, checked in both themes: 4.5:1 for text, 3:1 for control edges, icons and the focus ring). Live ratios for each pair are on the color page and on every component page under Accessibility → Contrast.
