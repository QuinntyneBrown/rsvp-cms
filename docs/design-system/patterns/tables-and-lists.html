Pattern

Data tables and lists

Tables are for comparing many records across the same columns; lists are for reading one record at a time. Both keep their filters, counts and actions in the same places on every page.

Overview

Built from table, list, chip (filters), search, badge (reply and status), checkbox (selection), pagination and empty state.

CollectionShapeColumns or lines
GuestsSelectable table with row actionsGuest (name + email), Group, Reply, Party, Updated
EventsSelectable tableEvent (name + type), Date, Invitees, Responses, Status
ResponsesRead-only tableGuest, Reply, Guests, Meal, Dietary, Message, Updated
Latest replies, upcoming events, notificationsList in a flush cardTitle, one meta line, optional badge or action
Public schedulePlain listTime, then what happens

When to use which

IfUse
People compare values down a column (reply, party size, meal)Table
Each record is read on its own and has one or two linesList
More than about 20 rowsPagination at 20 rows, with “Showing 1–20 of 84”; no infinite scroll, so people can share a page and reach the footer
People act on several records at onceCheckbox column, header select-all, and a bulk bar above the table
A narrow filter set (reply, status)Filter chips with aria-pressed; one pressed at a time, All by default
Free textSearch above the table; it matches names and emails
An order people chooseSortable headers with aria-sort; otherwise a Sort by select, as on Events

  2. Scan the first column names the record; badges carry status in words.
  3. Select checkboxes, then the bulk bar appears with the count.
  4. Act row actions for one, bulk bar for many, a dialog for destructive ones.
  5. Move pagination with the total.

States

  • Loading: the toolbar stays; the table becomes rows of .skeleton--control in the table frame.
  • Empty: the first-run empty state replaces the toolbar and the table (nothing to search yet).
  • No results: the toolbar stays with the query and filter visible; a compact empty state replaces the table.
  • Selected: the bulk bar shows the count and Clear selection; the header checkbox is checked when the whole page is selected and indeterminate when part of it is.
  • Error: the region error replaces the table; the toolbar stays.
  • Long: 20 rows per page; the header row sticks while the table scrolls inside its frame.

Responsive behaviour

  • Guests table (L2-081): below 48rem each row is a stacked card whose fields are labelled from td[data-label]::before, with the checkbox and every action visible. From 48rem it shows column headers and sortable columns.
  • Wider tables (responses) scroll sideways inside .table-wrap at SM; the page never does. The first column carries the name, so it stays readable when scrolled.
  • The toolbar wraps: search full width first, then the chips, then Export.
  • Lists stay lists at every width; meta lines wrap rather than truncate, except email addresses, which truncate with the full value in the row's name.
  • Pagination keeps Previous, the current page and Next at 360px; the other numbers wrap below.
  • Row actions are always visible under (hover: none), and every checkbox, chip and action has a 44×44px hit area under (pointer: coarse) (L2-084).

Accessibility

  • Tables have a <caption> (visually hidden when the page heading says the same), scope="col" headers and a labelled empty header for the checkbox and actions columns.
  • Every checkbox and icon-only action names its row: “Select Jonah Adeyemi”, “Remove Jonah Adeyemi”. Row actions follow DOM order left to right: Edit, then Remove (L2-086).
  • Sortable headers are buttons inside th[aria-sort]; the current direction is announced.
  • Filter chips sit in a role="group" with a label (“Filter by reply”) and use aria-pressed.
  • The bulk bar is a labelled toolbar; the selection count updates in a polite live region.
  • Pagination is a nav labelled “Pagination”, the current page has aria-current="page", and Previous/Next are labelled.
  • Badges say the status in words, so colour is never the only signal (SC 1.4.1); status text passes 4.5:1 in both themes (L2-085).

Keyboard

KeyAction
TabSearch → filters → Export → select-all → each row's checkbox and actions → pagination.
SpaceToggles a checkbox or a filter chip.
↑ / ↓Move focus to the same control in the previous or next row (L2-086).
EnterActivates a sort header, row action or page button.

Content

  • Column headers are short nouns: “Guest”, “Reply”, “Party”, “Updated”.
  • Empty cells show an en dash, never “N/A” or blank.
  • Relative times for the last two days (“2 min ago”, “Yesterday”), then dates (“Invited 19 Oct”).
  • Counts are exact and consistent: the pagination total, the no-results text and the event header use the same number.
  • Bulk bar: “{n} guests selected”, then verbs: “Send reminder”, “Move to group”, “Remove”.
