Pattern

Navigation and page structure

Organisers move between events and the sections of one event; guests see one event and nothing else. Every page tells you where you are without reading the URL.

Overview

Composed from sidebar, top bar, breadcrumb, page header, tabs, footer and skip link, inside the layout primitives.

ShellUsed byContains
OrganiserDashboard, events, every event section, notifications, accountSkip link, sidebar (Dashboard, Events, Notifications, Account, Sign out), top bar (menu, search, notifications, account menu), container
PublicEvent page, RSVP, invalid invitationSkip link, public top bar (the event name, or Invitely when the link cannot identify the event, plus “From Priya Natarajan”), narrow container, “Sent with Invitely” footer
Auth and errorSign in, password reset, 404, 403, 500, offlineSkip link, brand-only top bar, centred .auth-layout

  1. Where am I breadcrumb and the page title (the event name).
  2. What is this the current tab and its aria-current.
  3. What can I do page header actions, primary last.
  4. Where else sidebar and tabs, the same order on every page.

States

  • Current page: the sidebar link and the event tab carry aria-current="page" and the accent-subtle look.
  • Counts: the Notifications link and the top-bar notifications link carry the unread count in their accessible name (“Notifications, 3 unread”).
  • Read-only event (invites closed): the tabs stay, actions that would change the event hide, and a banner says why.
  • Drawer open (below 48rem): the menu button sets aria-expanded="true"; the drawer traps focus like a dialog, Esc closes it and focus returns to the menu button (L2-080, L2-086).

Responsive behaviour

  • Shell (L2-080): from 48rem the sidebar is persistent and the menu button hides. From 36rem to 47.99rem the menu button opens the sidebar as a 20rem drawer from the left (--layout-drawer-width); below 36rem it opens as a full-width panel.
  • Breadcrumbs collapse to the parent link (“‹ Events”) below 48rem.
  • Event tabs never wrap: they scroll sideways inside the tab bar, and the current tab is scrolled into view.
  • Page-header actions move under the title below 48rem; the primary becomes full width.
  • Public pages (L2-082): one column with a 16px gutter and a full-width form below 36rem; one column in --layout-container-narrow (42rem) from 36rem; from 62rem Details and Schedule sit side by side in --layout-container-guest (60rem). The RSVP form never exceeds --layout-form-max (45rem). The footer stays at the end of the content, not fixed.

Accessibility

  • Landmarks: header (top bar), nav aria-label="Primary" (sidebar), nav aria-label="Breadcrumb", nav aria-label="Event sections", main, footer.
  • A skip link to #main is the first focusable element on every page (L2-086; SC 2.4.1).
  • Under (pointer: coarse) every link and button in the shell has a 44×44px hit area (L2-084).
  • Navigation appears in the same order with the same names on every page (SC 3.2.3, 3.2.4).
  • Each page has a unique title: “Guests · Maya’s 30th birthday · Invitely”.
  • The sticky top bar never hides the focused element: scroll-padding-top equals its height plus 16px (SC 2.4.11).
  • Event tabs are links, not ARIA tabs: Tab moves between them and Enter follows them, as people expect from navigation.

Keyboard

KeyAction
TabSkip link → sidebar → top bar → breadcrumb → page actions → tabs → content.
EnterFollows a link; on the menu button opens the drawer.
EscCloses the drawer or the account menu and returns focus to its button (L2-086).

Content

  • Navigation labels are nouns: “Events”, “Guests”, “Responses”. Page actions are verbs: “Add guest”, “Import CSV”.
  • The page title is the thing, not the section: the event name on every event tab, with the section in the tab and the document title.
  • Breadcrumb items use the same words as the pages they link to.
  • Public pages speak as the host: “From Priya Natarajan”; Invitely appears only in the footer.
