Pattern

Empty and error states

An empty or failed region still tells people where they are, why it is empty, and the one thing to do next.

Overview

Built from empty state and error page. Every collection in the mocks (events, guests, emails, responses, notifications, page blocks) has an empty, an error and, where it can be filtered, a no-results state; the app has 404, 403, 500, offline and invalid-invitation pages.

Structure

No results on the events list: the search and filter chips stay put and show what is active; the empty state is compact, names the search and the filter, and offers both ways out.

Your filters are on: Invites closed. Clear them to see every event.

Compact empty state under the filters; Clear filters is primary because the filter, not the search, hides the results.

  1. Icon in a 64px circle; accent, neutral or danger tone.
  2. Title what is true now, as a heading at the right level.
  3. Text one or two sentences: why, and what happens next.
  4. Actions one primary, at most one secondary; none when nothing helps.

States

  • When a region is empty or failed, the page header only shows facts that loaded: “Mon 19 Oct”, not “1 event is taking invites” from data that is missing.
  • Header actions that need items (Export, Mark all as read) hide while the region is empty.
  • Error pages use the brand-only top bar; the invalid-invitation page keeps the public top bar with the host’s name (“From Priya Natarajan”) so guests know who to ask.
  • Offline shows a banner over the last loaded page when there is one; the full offline page is only for a cold start with nothing loaded.

Responsive behaviour

  • Empty states are centred and cap their text at 36ch at every width.
  • Actions wrap and centre; on phones the primary stays first in reading order.
  • Compact empty states sit in the content column under the filters; full ones replace the region, with 48px block padding.
  • Error pages centre in the viewport with .auth-layout; nothing scrolls sideways at 320px.

Accessibility

  • The empty-state title is a real heading at the level the region's heading would have been (h2 inside a page, h1 on an error page).
  • The icon is decorative (aria-hidden); the title and text carry the meaning.
  • No-results text is announced through the list's live status (“0 events match”) when the filter changes, without moving focus.
  • After Try again, focus stays on the button while the region reloads with aria-busy; the result is announced.
  • Error pages have a unique <title> (“Page not found · Invitely”) and a skip link like every page.

StateTitleTextExample
First runThe goal or what is missingHow to start and what happens next“No invitees yet” · “Import a CSV from a spreadsheet, or add people one at a time.”

Caught upA plain, warm factWhere new items will come from“You’re all caught up”

ForbiddenYou don’t have access to this {thing}Who can give access“Ask Priya Natarajan to add you as a co-host.”
  • Never blame the person (“You entered a bad link”); say what is true (“This invitation link doesn’t work”).
  • Guests never see organiser words: no “dashboard”, “admin” or “co-host” on public pages.
