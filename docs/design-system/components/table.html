Table

Lists events, guests and responses with sortable columns, row selection, bulk actions and row actions; becomes labelled cards below 768px.

Overview

Use for records people compare across columns. Always inside .table-wrap (horizontal scroll, never page scroll) with a <caption>. Features: sortable headers (aria-sort), selection column + bulk bar, row actions, numeric columns right-aligned, dense size, and the stack layout (L2-081: below MD each row is a card with labelled fields and all actions visible).

Row-action focus order (decision): actions sit in DOM order, left to right, identical to the visual order — e.g. Edit then Remove; the destructive action is always last. Tab visits the row checkbox, the row link, then each action in that order. Inside the table grid (L2-086 arrow keys, roving tabindex): ↑/↓ move to the same control in the previous/next row, ←/→ move between the controls of a row in DOM order (checkbox → name link → Edit → Remove), Home/End go to the first/last control of the row. Row actions are never hidden from keyboard users: they become visible on :focus-within, and are always visible on touch (L2-084).

Anatomy

  1. CaptionVisually hidden name.
  2. HeaderSunken background, label font, sticky; sortable headers hold a button.
  3. SelectionCheckbox per row + select-all.
  4. Cell--space-3 × --space-4, --text-body-sm.
  5. Row actionsGhost sm Buttons, DOM order = visual order.

Responsive behaviour

  • Below MD (768px) a table--stack table renders each row as a card: header hidden visually, each cell shows its data-label, actions always visible (L2-081 AC1). Used for Guests, Events and Responses.
  • MD+: column headers and sortable columns (L2-081 AC2).
  • A wide table at SM that is not stacked scrolls inside .table-wrap; the page never scrolls sideways (AC3).
  • Touch: row actions always visible (hover: none and pointer: coarse, L2-084).

Theming

Header --color-bg-surface-sunken; hover --color-bg-subtle; selected --color-accent-subtle.

Accessibility

Role and pattern

Native <table> with <caption>, scope="col"; sortable headers contain a <button> and the th carries aria-sort; selected rows aria-selected="true". Arrow-key movement follows the APG Grid navigation model with a roving tabindex while keeping table semantics.

Keyboard

KeyAction
TabEnters the table at the last-focused control (one tab stop), then leaves it.
↑ / ↓Same control in the previous / next row.
← / →Previous / next control in the row, DOM order: checkbox → name → Edit → Remove.
Home / EndFirst / last control in the row.
Space on checkboxSelect row; bulk bar count updates politely.
Enter on header buttonSort; the new order is announced (“Sorted by guest, ascending”).

Focus

Row-action focus order (decision): actions sit in DOM order, left to right, identical to the visual order — e.g. Edit then Remove; the destructive action is always last. Tab visits the row checkbox, the row link, then each action in that order. Inside the table grid (L2-086 arrow keys, roving tabindex): ↑/↓ move to the same control in the previous/next row, ←/→ move between the controls of a row in DOM order (checkbox → name link → Edit → Remove), Home/End go to the first/last control of the row. Row actions are never hidden from keyboard users: they become visible on :focus-within, and are always visible on touch (L2-084).

Labelling

Caption names the table. Row checkboxes “Select {name}”; actions “Edit {name}” (visible word first). Icon-only cells are not allowed.

Motion

Row-action reveal fades over --duration-fast.

Touch

Row actions are 32px on fine pointers (≥ 24px, WCAG 2.5.8, decision for dense tables) and 44px on coarse pointers, always visible.

Content

  • Column headers are nouns, sentence case.
  • Dates relative when recent (“2 min ago”), absolute otherwise (“Invited 19 Oct”).
  • Empty cells show “—” with hidden “none”.
