Component · Data display

Table

Tables show records people compare across columns: the guest list, the events list, scheduled emails and RSVP responses. Rows are scannable, sortable and selectable, and they scroll inside their own frame on phones.

Overview

Use a table when people compare values across records: who replied, how many guests, which meal. Use a list when each record is read on its own (notifications, latest replies), and a description list for the details of one record.

  • Default, stacking is the guest list (.table--stack): a selection column, a row header with name and email, badges for status, and row actions. Below 48rem it becomes stacked cards with labelled fields (L2-081).
  • Dense is for the responses table, where organisers read many short cells (meal, dietary needs, message).
  • Sortable headers are buttons inside <th aria-sort>; the events list sorts by date.
  • Selectable adds a checkbox column and a .bulk-bar that appears once anything is selected.
  • Tables always sit in .table-wrap, which draws the frame; tables that do not stack scroll sideways inside it on narrow screens.

Anatomy

  1. Selection cellinput.checkbox labelled “Select Jonah Adeyemi”; .col-select keeps it narrow.
  2. Header cell<th scope="col"> on --color-bg-surface-sunken, --text-label, sticky in a bounded wrap.
  3. Status cellA badge: colour, dot and text.
  4. Row header<th scope="row"> with .list__title and .list__meta; names the row for screen readers.
  5. Row actionsSmall ghost buttons in td.row-actions; shown on hover, focus and touch.
  6. Frame.table-wrap: 1px --color-border-default, --radius-lg, horizontal scroll.

Variants

Pick the variant from the job, not the data size. All variants share the same cell padding scale, header style and row states.

Responsive behaviour

Two strategies, chosen per table (L2-081):

  • Stack (.table--stack, the Guests table): mobile first, rows are cards. The header row is hidden, every cell shows its column name from td[data-label], the row header (guest name) leads, the checkbox sits at the left, and every row action is visible. At 48rem (--layout-breakpoint-md) and up it is a normal table with column headers, sorting and hover-revealed actions.
  • Scroll (default): wide tables such as responses and emails keep their columns and scroll sideways inside .table-wrap at small widths, so the page itself never scrolls horizontally (WCAG 1.4.10 allows two-dimensional scroll for data tables). Use .table--sticky-col to keep the identifying column visible.
  • Row actions are always visible when the device cannot hover (@media (hover: none)) and in stacked cards (L2-084).
  • Under (pointer: coarse) row-action buttons, sort buttons and the selection cell (a <label> around the checkbox) grow to 44 × 44px (--target-comfortable).
  • The bulk bar wraps: the count stays on the first line and the buttons flow beneath it at 360px.
  • Toolbars above a table (search, filter chips, export) are a .cluster and wrap onto new lines.

Theming

The table reads semantic tokens only: --color-bg-surface for the frame, --color-bg-surface-sunken for the header, --color-border-default for row dividers, --color-bg-subtle for hover and --color-accent-subtle for selection. Density is two component tokens, --table-cell-y and --table-cell-x.

/* A roomier table for a print view */
.print .table { --table-cell-y: var(--space-4); --table-cell-x: var(--space-6); }

In dark the header sits on --palette-gray-925, below the gray-900 surface, so the header reads as recessed rather than raised; selected rows use blue-950 with light text.

Accessibility

Role and pattern

A native <table> with a <caption> (visually hidden when the page heading already names it), <th scope="col"> headers and a <th scope="row"> row header. It is a static table, not an ARIA grid: Tab moves between the controls inside it. Sorting follows the APG sortable table example.

Keyboard

KeyAction
Tab / Shift+TabMoves through the sort buttons, checkboxes, links and row actions in reading order.
SpaceToggles a row checkbox.
↑ / ↓Moves focus to the same control in the previous or next row (scripted roving focus, L2-086), so long lists need not be tabbed through cell by cell.
Enter, SpaceActivates a sort button (cycles ascending, descending) or a row action.
Shift+Scroll / trackpadScrolls a wide table sideways; the wrap is focusable only when it scrolls, with tabindex="0" and a label.

Focus

Focus inside a row reveals its actions (:focus-within), so keyboard users never tab to invisible buttons. Actions follow DOM order left to right: Edit, then Remove. Sort buttons use the shared ring; after sorting, focus stays on the header button that was pressed.

Labelling

Each checkbox is labelled with the row (“Select Jonah Adeyemi”); a header checkbox, when present, is “Select all 84 guests”. Row action buttons include the object (“Edit Jonah Adeyemi”). aria-sort sits on the sorted <th> only and announces the direction. The bulk bar is a labelled region and its count is in a live region so “2 guests selected” is announced.

Touch

On coarse pointers the selection cell’s label, the sort buttons and the row actions are 44 × 44px; row actions are always visible without hover and in stacked cards.

Content

  • Column headers are nouns in sentence case: “Guest”, “Reply”, “Party”, “Updated”.
  • The row header carries the name a person would say, with one line of meta beneath (email, event type).
  • Status cells use the badge vocabulary: Attending, Waiting, Declined; Sent, Scheduled; Invites open, Invites closed.
  • Empty cells show an em dash “—”, never blank and never “N/A”.
  • Relative times for the last week (“2 min ago”, “Yesterday”), then dates (“Invited 19 Oct”).
  • Numbers right-aligned with tabular figures (.num).
