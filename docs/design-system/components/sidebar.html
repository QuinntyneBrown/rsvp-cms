Sidebar

The sidebar is the organiser's map of Invitely: Dashboard, Events and Notifications, then their account. It is always visible on laptops and slides in from the menu button on smaller screens.

Overview

Every organiser page (117 of the mocks) sits in the .sidebar-layout shell: sidebar on the left, top bar and page on the right. Guest pages and auth pages have no sidebar.

  • Use it for the few top-level destinations an organiser moves between all day. Five items is the ceiling before it needs groups.
  • Use tabs for sections inside one event (Overview, Page, Guests, Emails, Responses, Settings), not more sidebar items.
  • Use the top bar for search and the account menu; the sidebar's Account group is the full-page version of the same destinations.

Anatomy

  1. BrandLogo and “Invitely”, a link to the dashboard; --text-h4, 16px gap below (was an inline style).
  2. Nav link44px tall, icon + label, --radius-md; muted until hovered.
  3. CountCount badge pushed to the end; its aria-label says what it counts.
  4. Group labelOverline text, --color-fg-subtle; not a heading, not focusable.
  5. ActionSign out is a button in a form that posts, styled as a nav link.

Variants

One sidebar, with optional parts. Groups appear only when there are two kinds of destination (the work, and the account).

As a drawer below 64rem

Below 64rem the sidebar is hidden. The top bar's menu button sets data-open="true" on it, which fixes it to the left edge at min(16rem, 85vw) with --shadow-4 over a backdrop; Esc or the close button removes the attribute.

Responsive behaviour

  • 64rem (--layout-breakpoint-lg) and up: the sidebar is a 16rem column, sticky, full viewport height, and scrolls on its own if it ever outgrows the screen.
  • Below 64rem: hidden. The top bar's menu button opens it as a drawer (data-open="true") over a .backdrop; the page behind is inert.
  • Choosing a link in the drawer navigates and closes it; focus lands on the new page's skip link as with any navigation.
  • Labels never truncate at 16rem; “Notifications” plus a count is the longest label and fits.

Theming

Reads --color-bg-surface with a --color-border-default right edge. Links use muted text, --color-bg-subtle on hover, and the accent-subtle pair for the current page, so the current item reads as selected in both themes without a heavy fill.

/* Stronger current item for a high-contrast brand theme */
[data-theme="partner"] .nav-link[aria-current="page"] { background: var(--color-accent); color: var(--color-fg-on-accent); }

Accessibility

Role and pattern

A <nav aria-label="Primary"> landmark of plain links; not an ARIA menu or tree. As a drawer it follows the APG modal dialog rules: focus moves in, is held there, Esc closes and returns focus to the menu button.

Keyboard

KeyAction
Tab / Shift+TabMoves through brand, links and Sign out in order.
EnterFollows a link; on Sign out submits the form.
EscDrawer only: closes it and returns focus to the menu button.

Focus

The standard ring, offset inside the 16px padding so it is never clipped by the sidebar's own scroll.

Labelling

The landmark is “Primary”. The current link has aria-current="page". The count badge's aria-label="3 unread" makes the link read “Notifications, 3 unread”. Icons are aria-hidden.

Motion

Hover colours change over --duration-fast. The drawer slides in over --duration-slow with --ease-enter; reduced motion makes it appear at once.

Touch

Every link is 44px tall and the full sidebar width, the comfortable target size.

Content

  • One or two words, nouns for places: “Dashboard”, “Events”, “Notifications”, “Account”.
  • “Sign out”, not “Log out” or “Logout”.
  • Counts show unread or needing attention only; never totals.
  • Group labels are short nouns in sentence case (rendered in capitals by CSS): “Account”.
