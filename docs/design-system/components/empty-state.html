Empty state

When a list, page or panel has nothing in it, an empty state says why and offers the one action that fills it: create the first event, clear the search, try again.

WCAG 2.2 AAStatus: stable

Overview

Use an empty state in place of a list, table or panel that has no content. It replaces the content, not the page: the shell, page header and tabs stay. For a whole page that cannot be shown (404, 403, 500, offline) use an error page, which is built from the same parts.

  • First run: nothing has been created yet (“No events yet”, “Start with a hero”). Explains what the thing is and offers to create one.
  • No results: a search or filter matched nothing (“No responses match ‘allergy’”). Compact; offers to clear.
  • Permission: the content exists but this person cannot see it. Neutral icon; says who can grant access.
  • Error: the content failed to load (“We couldn’t load your emails”). Danger icon; reassures and offers Try again.

Anatomy

  1. Icon64px circle, accent-subtle (danger for errors, subtle for permission); 24px icon, aria-hidden.
  2. Title--text-h3 (--text-h4 when compact); a heading at the right level for the page.
  3. TextOne or two sentences, max 36ch, --color-fg-muted.
  4. ActionsOne primary action, an optional secondary; omitted entirely when there is nothing to do.

  • Retrying: Try again goes busy; on success the content replaces the empty state, on failure the state stays and a toast says it failed again.
  • Leave .empty__actions out when there is no action; an empty actions container is hidden by CSS but should not be written.

Responsive behaviour

  • Centred at every width; text wraps at 36ch.
  • Actions wrap onto two lines on phones, primary first.
  • Inside a table, the empty state replaces the table body area, not the whole card, so the filter bar stays usable.

Theming

The icon circle reads --color-accent-subtle / --color-fg-accent; .empty--error switches to --color-danger-bg / --color-danger-icon, .empty--neutral to --color-bg-subtle / --color-fg-muted. Text is --color-fg-muted.

Accessibility

Role and pattern

Plain content: a heading, a paragraph and real buttons or links. No ARIA role. The title is a heading at the level the replaced content would have had (h2 inside a page; h1 only on error pages).

Keyboard

KeyAction
TabReaches the actions in order: primary, then secondary.
EnterActivates.

Focus

An empty state that replaces content after a search does not take focus; the search field keeps it. After Clear search, focus stays on the field.

Labelling

The icon is decorative (aria-hidden). Link text works alone: “Create your first event”, not “Get started”. When a search returns nothing, the result count is announced through the page’s status region.

Content

  • Title: the situation, plainly: “No events yet”, “No responses match ‘allergy’”, “We couldn’t load your emails”.
  • Text: what the thing is for, or what was searched, and the way out. Errors start with reassurance: “Nothing was sent or changed.”
  • The primary action repeats the title’s promise: “Create your first event”, “Clear search”, “Try again”.
  • The text and the action must agree: if the text says “go back to events”, the link goes to Events.
