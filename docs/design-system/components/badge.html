Badge

A badge is a short, non-interactive label for status: a guest is Attending, an email is Scheduled, an event’s invites are open. A count badge says how many unread notifications are waiting.

WCAG 2.2 AAStatus: stable

Overview

Use a badge for the state of a record, inside a table cell, a list row or a description list. Use a chip when people can press it, and an alert when the status needs explanation or action.

  • Tone carries meaning, consistently: success = done or yes (Attending, Sent); warning = needs attention (Waiting, 2 bounced); info = upcoming or active (Scheduled, Invites open); neutral = finished or no (Declined, Invites closed, Opens 26 Oct); danger = failed (Bounced).
  • Every badge has a leading dot and text, so colour is never the only signal (WCAG 1.4.1).
  • Solid is for a single “New” marker on a light list; use it sparingly.
  • Count is a number on --color-danger-solid for unread notifications; no dot.

Anatomy

  1. Dot8px circle in currentColor, hidden on count badges.
  2. Label--text-overline: 12px semibold, uppercase, wide tracking. One or two words.

Sizes

Badges have one size: 24px tall, 8px side padding. They sit inside text-height rows, so a second size would only add inconsistency.

States

Badges are not interactive and have no hover, focus or disabled state. The only change is the tone, which follows the record.

Responsive behaviour

  • Badges never wrap or truncate (white-space: nowrap); keep labels to two words so they fit a table cell at 360px.
  • In a list row the badge stays at the end and the title wraps instead.
  • Counts above 99 read “99+” with the full number in the label.

Theming

Each tone sets two component tokens, --badge-bg and --badge-fg, from the status tokens (--color-{status}-bg, --color-{status}-fg). In dark the backgrounds become deep tints (green-950, amber-950…) and the text pale (green-300…), keeping every pair above 4.5:1.

/* A brand theme that wants quieter neutral badges */
[data-theme="partner"] .badge { --badge-bg: var(--color-bg-surface-sunken); }

Accessibility

Role and pattern

Plain inline text in a <span>; no role. The text is read in place (“Attending”). Count badges carry an aria-label with the noun; when the count changes live, announce it through a polite live region, not by giving the badge role="status".

Keyboard

KeyAction
TabNever stops on a badge; it is not interactive.

Focus

None. A badge inside a link (navigation count) is part of that link’s name and focus ring.

Labelling

The visible text is the label. Uppercase is applied in CSS, so screen readers read “Attending”, not letter by letter. The dot is a pseudo-element and is not announced.

Content

  • One or two words, sentence case in the source (CSS uppercases it): “Attending”, “Invites open”.
  • Use the same word for the same state everywhere: a guest is “Waiting”, not “Pending” on one page and “No reply” on another.
  • Include a number when it is the point: “2 bounced”, “Open · 19 days left”.
  • Dates in badges are short: “Opens 26 Oct”.
