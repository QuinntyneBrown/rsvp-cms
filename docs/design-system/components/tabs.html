Tabs

Tabs move between views of the same thing. In Invitely the main use is the event bar (Overview, Page, Guests, Emails, Responses, Settings), which is navigation between pages; true in-page tabs switch panels without leaving the page.

Overview

Every event page in the mocks (79) carries the same six-item bar under the page header. Each item is a separate page with its own URL, so the bar is navigation: a <nav> of links with aria-current="page", not ARIA tabs. Screen readers announce it as links, browser back works, and each section can be bookmarked.

  • Link tabs (<nav class="tabs"> + <a class="tab">): sections that are pages. This is the default.
  • APG tabs (role="tablist" + <button role="tab">): panels already on the page that swap in place with no URL change, such as the HTML and plain-text versions of an invitation. No mock uses one yet.
  • Use filter chips, not tabs, to filter a list (the guest list's All / Waiting / Attending / Declined).
  • Use the sidebar for top-level destinations.

Anatomy

  1. Tab44px tall, label in --text-label, muted until hovered or current.
  2. Indicator2px --color-accent bar on the current tab, sitting on the rail; --radius-xs top corners.
  3. Rail1px --color-border-default line under the whole bar.

Responsive behaviour

  • Tabs never wrap to two rows. The bar scrolls horizontally (overflow-x: auto) with the scrollbar hidden.
  • Base (phones): the six event tabs need 455px and get 328px at 360px wide, so the trailing 32px fades out (mask-image) to show there is more. From 48rem the fade is removed, where all six fit.
  • The page scrolls the current tab into view on load (scrollIntoView({ inline: "nearest" })), so “Settings” is never hidden off the end.
  • Tab labels never truncate; keep them to one word.

Theming

Reads --color-fg-muted (resting), --color-fg-default (hover), --color-fg-accent and --color-accent (current), and --color-border-default for the rail. In dark the accent indicator is blue-300 on gray-950, well above 3:1.

/* Thicker indicator for a partner theme */
[data-theme="partner"] .tab::after { height: var(--space-1); }

Accessibility

Role and pattern

Link tabs: a <nav aria-label="Event sections"> landmark of links; the current one has aria-current="page". No ARIA roles. APG tabs: the APG Tabs pattern with automatic activation: role="tablist", role="tab" with aria-selected and aria-controls, role="tabpanel" with aria-labelledby and tabindex="0".

Keyboard

KeyAction
TabLink tabs: each tab is a stop. APG tabs: one stop for the selected tab, then the panel.
EnterLink tabs: opens that section.
← / →APG tabs: moves to the previous/next tab and selects it; wraps at the ends.
Home / EndAPG tabs: first/last tab.
SpaceAPG tabs: selects the focused tab (already selected under automatic activation).

Focus

The ring is drawn inset (outline-offset: -2px) so the scrolling bar never clips it. On APG tabs focus stays in the tablist while arrowing; Tab moves to the panel.

Labelling

The nav or tablist has an aria-label (“Event sections”, “Invitation format”). Counts are read as part of the tab name (“Attending 52”). Panels are named by their tab.

Motion

The indicator colour fades over --duration-fast; it does not slide between tabs. Zeroed by reduced motion.

Touch

Tabs are already 44px tall (--target-comfortable), meeting L2-084 under coarse pointers; the horizontal scroll is a native swipe.

Content

  • One word per tab, a noun for the section: “Overview”, “Guests”, “Responses”.
  • The same six event sections in the same order on every event page (WCAG 3.2.3 consistent navigation).
  • Counts only when they help choose: “Responses” does not need one; a status filter does.
