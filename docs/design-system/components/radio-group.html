Radio group

A radio group asks one question with two to five visible answers, and exactly one can be chosen: will you attend, who gets this email, what kind of event.

WCAG 2.2 AAStatus: stableNative <input type="radio">

Overview

Use a radio group when the options are mutually exclusive, there are few of them, and seeing all of them helps the decision. With six or more options, or options people already know (time zones, meals), use a select. For independent options use checkboxes.

  • Vertical (default): the RSVP form's “Will you attend?”, the invite dialog's “Recipients” and the new-event form's “Event type”.
  • Horizontal (.choice-group--inline): short, parallel answers such as numbers.
  • Card (.choice--card): each option is a bordered card with a description; for choices that deserve weight and a sentence of explanation. No mock uses cards yet; the new-event form's event type (vertical radios with descriptions) is the natural candidate, shown below as cards.

Anatomy

  1. LegendThe question, in --text-label; it names the group for screen readers.
  2. Radio20px circle, 1px --color-border-strong; selected fills with --color-accent and an 8px --color-fg-on-accent dot.
  3. LabelThe answer, in body text; clicking it selects the option.
  4. Description (optional)<small> in --color-fg-muted under the label.

Sizes

Radios have one size: a 20px circle in a row at least 24px tall. Use card-style options when an answer needs more room, not a bigger circle.

States

Invalid group

Will you attend?
Choose whether you’re coming.
The RSVP form's error when nobody chose an answer: each radio is aria-invalid and the fieldset points at the message.
HTML
<fieldset id="rg-inv" aria-describedby="rg-inv-err">
<legend>Will you attend?</legend>
<div class="choice-group">
<label class="choice">
<input type="radio" name="rg-inv-r" aria-invalid="true"><span class="choice__text">Joyfully accepting</span></label>
<label class="choice">
<input type="radio" name="rg-inv-r" aria-invalid="true"><span class="choice__text">Regretfully declining</span></label></div>
<span class="field__error" id="rg-inv-err">Choose whether you’re coming.</span></fieldset>

Both themes

  • No default selection when the answer is a personal decision (attending). Pre-select only a safe, common answer, such as “All 84 invitees”.
  • Disabled options stay visible with a reason nearby: for example, “Only people who haven’t replied” makes no sense for a first invitation, so it would be disabled with “Available for reminders” beside it.
  • Invalid applies to the whole group; never mark one option as the wrong one.

Responsive behaviour

  • Vertical groups are the same at every width.
  • Horizontal groups wrap; if they wrap at 360px the answers are too long, so make the group vertical.
  • Card groups are one column below 36rem and auto-fit columns of at least 12rem above it; each card is a full-width target on phones.

Theming

Radios share the checkbox's tokens: --color-bg-surface, --color-border-strong, --color-accent, --color-fg-on-accent and --choice-size. Card options add --color-accent-subtle for the selected fill and --radius-md corners.

In dark the selected card reads as blue-950 with a blue-300 edge; the label stays --color-fg-default, which passes 4.5:1 on the accent-subtle fill.

Accessibility

Role and pattern

Native radios with a shared name, grouped by <fieldset> and named by <legend>. This meets the APG Radio Group pattern without ARIA roles.

Keyboard

KeyAction
TabMoves into the group, onto the selected radio (or the first one if none is selected), then out of the group.
↓ / →Selects the next option, wrapping at the end.
↑ / ←Selects the previous option.
SpaceSelects the focused option if none is selected yet.

Focus

The shared ring draws around the circle; on card options it draws around the whole card instead (:has(input:focus-visible)).

Labelling

The legend is the group's name; each label is the option's name; descriptions are inside the label so they are read with it. Errors are linked to the fieldset with aria-describedby, and the error summary links to the fieldset's id.

Motion

Fill, border and card background change over --duration-fast; instant under reduced motion.

Touch

Each label row is at least 24px tall; card options are at least 56px tall with 12px between cards, which suits thumbs on the public RSVP page.

Content

  • The legend is a question: “Will you attend?”, “Who should get this email?”.
  • Answers are parallel and short; warm wording is fine on guest pages (“Joyfully accepting”, “Regretfully declining”), plain wording on organiser pages.
  • Put numbers and consequences in the description: “All 84 invitees · Each person gets a personal link”.
  • Avoid “Other” unless it opens a text field.
