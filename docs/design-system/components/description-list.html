Description list

A description list pairs a label with a value: when and where the party is, when invitations open and close, what a guest replied. Labels sit beside values on wider screens and above them on phones.

Overview

Use a description list for the facts of one thing, where each value needs its label to make sense. Use a table to compare the same facts across many records, and a list for records that need no labels.

  • Horizontal (default from 36rem): labels in a max-content column, values beside them. Event details, invite window, the guest’s saved reply.
  • Stacked (.dl--stacked, and every list below 36rem): label above value, for long values or narrow columns.

Anatomy

  1. Term<dt>, --text-label in --color-fg-muted; a noun in sentence case.
  2. Description<dd>, body text in --color-fg-default; text, a date, a badge or a link.
  3. GridTwo columns from 36rem: max-content and 1fr, gaps --space-2 × --space-6.

Sizes

One size; the description list inherits body text and adapts its columns to the width.

States

A description list is static: it has no interactive states of its own. Links or badges inside a value keep their own states. While the record loads, show skeleton text in each <dd>; when a value is unknown, show “Not set” in --color-fg-muted, never an empty cell.

Responsive behaviour

  • Mobile first: below 36rem (--layout-breakpoint-sm) every list is stacked, label above value, with 8px after each value.
  • From 36rem labels move into a max-content column; keep labels short (one or two words) so the value column stays wide.
  • Long values (addresses, messages) wrap within their column; never truncate them.

Theming

Reads --color-fg-muted for terms and inherits the value colour. It has no background, border or component tokens; the surrounding card provides the surface.

Accessibility

Role and pattern

Native <dl>, <dt>, <dd>; screen readers announce the term with its description. Each <dt> is followed directly by its <dd> elements (no wrapping divs other than the allowed <div> per group).

Keyboard

KeyAction
TabOnly interactive values (links, buttons) take focus; the list itself does not.

Focus

No focus of its own; links inside values show the shared ring.

Labelling

The term is the label. Precede the list with a heading (“Details”, “Invite window”) so it can be found by heading navigation.

Content

  • Terms are short nouns in sentence case: “When”, “Where”, “Opens”, “Closes”, “Meal”.
  • Dates in values are complete: “Sat 14 Nov 2026, 7:00 pm”.
  • Use “Not set” for a missing value; never an em dash alone in a description list.
  • Counts read as sentences when they need context: “3 existing guests”, “3 rows with errors”.
