Component · Navigation

Top bar

The top bar is the first thing on every page. For organisers it holds the navigation button, search, notifications and the account menu; on guest pages it names the event and who sent it.

Overview

Every one of the 166 mocks has a top bar. It is a <header> landmark that sticks to the top of the viewport (--z-sticky) so search and notifications are always one tab stop away.

  • App (organiser pages inside the sidebar shell): menu button below 64rem, search, notifications, account avatar.
  • Public (event page, RSVP, invalid invitation): the event name as the brand, links back to the event page, and “From Priya Natarajan” so guests know who invited them.
  • Auth (sign-in, forgot and reset password, error pages outside the shell): brand only.

Do not put page actions in the top bar; they belong in the page header. Do not add a second row of navigation; event sections use tabs under the page header.

Anatomy

  1. Menu buttonGhost icon button, shown below 64rem only; opens the sidebar as a drawer. aria-expanded + aria-controls="sidebar".
  2. Search<form role="search"> with a visually hidden label; grows to fill, capped at 28rem.
  3. NotificationsGhost icon button; the unread count is in its name and its tooltip.
  4. AccountSmall avatar button with initials; opens the account menu.

Variants

Three variants, chosen by the shell the page uses, never by the page itself.

Sizes

The top bar has one height: --layout-topbar-height (56px) at every breakpoint.

States

The bar itself has no states; its controls do. Hover, focus and active are forced with data-state. When the drawer is open the menu button's name becomes “Close navigation”, its icon a cross, and aria-expanded="true".

Responsive behaviour

  • Base (phones): menu button, search filling the remaining width, notifications and avatar. Search keeps its icon and placeholder; at 360px the placeholder truncates rather than wrapping.
  • 64rem (--layout-breakpoint-lg) and up: the menu button is removed (display: none) because the sidebar is permanently visible; search caps at 28rem.
  • The bar's horizontal padding is --layout-margin, so its edges line up with page content at every breakpoint (16, 32, 48px).
  • Height stays 56px; scroll-padding-top on html matches it so in-page links and focused fields are never hidden under the sticky bar (WCAG 2.4.11).

Theming

The bar reads --color-bg-surface with a --color-border-default bottom edge, so in dark it sits one step above the canvas (gray-900 on gray-950). Its controls are ghost buttons and an avatar, which bring their own tokens.

/* A branded public bar for a partner theme */
[data-theme="partner"] .topbar { background: var(--color-bg-surface-raised); }

Accessibility

Role and pattern

<header class="topbar"> is the banner landmark. Search is a <form role="search">. The menu button follows the APG Disclosure pattern; the account avatar is an APG Menu Button (aria-haspopup="menu", aria-expanded).

Keyboard

KeyAction
TabSkip link, then menu button (below 64rem), search, notifications, account, in that order.
Enter / SpaceMenu button toggles the drawer; account opens its menu with focus on the first item.
EscCloses the drawer or the account menu and returns focus to the button that opened it.
Enter in searchSubmits the search form.

Focus

The standard ring on every control. The bar is sticky, so a focused element further down the page scrolls to sit below it, never under it.

Labelling

Icon-only controls carry the full name: “Open navigation”, “Notifications, 3 unread”, “Account menu for Priya Natarajan”. Tooltips repeat the name for sighted pointer users. The search label is visually hidden but present.

Motion

Only the controls animate (hover colour, --duration-fast). The drawer it opens slides with --duration-slow; both are zeroed by reduced motion.

Touch

Icon buttons are 40px square and the avatar 32px, with 12px between them. The bar is 56px tall, so every control sits in a comfortable band away from the screen edge.

Content

  • Search placeholder says what it searches: “Search events and guests”. The label says the same, hidden.
  • Counts belong in names: “Notifications, 3 unread”; never a bare “3”.
  • Public bars name the event exactly as the organiser wrote it and the host as “From Priya Natarajan”, not “Hosted by” or an email address.
  • The product name “Invitely” appears only on organiser and auth pages; guest pages are about the event.
