Button

Buttons let organisers and guests do something: save the event, send invitations, delete a guest, send an RSVP. One primary button per view says what matters most.

Overview

Use a button when activating it changes something: it submits, creates, deletes, opens a dialog or starts a process. Use a link when it only takes the person somewhere (in the mocks, “View public page” and “New event” are links styled as buttons because they navigate). Use a menu when one trigger offers several actions.

  • Primary is the one action the view exists for: “Send my RSVP”, “Schedule invitations”, “Save changes”. Never two per view.
  • Secondary (the default look) is for everything else that is still an action: “View public page”, “Preview”.
  • Ghost sits in dense surfaces: the top bar, table rows, card headers, the CMS block toolbar (“Move up”, “Collapse”).
  • Link looks like a link but behaves like a button; for low-emphasis actions such as “Copy link”.
  • Danger is for destructive actions and appears only in the danger zone of settings and inside confirmation dialogs (“Delete event”, “Remove 3 guests”).

Anatomy

  1. Leading icon (optional)1.25em square, inherits the label colour, aria-hidden.
  2. LabelA verb phrase in sentence case; it is the accessible name.
  3. ContainerHeight from --control-height-*, --radius-md corners, 1px border, horizontal padding --space-3/4/6.

Variants

Variants change emphasis, not meaning. Pick by how much attention the action deserves on this view.

Emphasis from highest to lowest; danger is reserved for destructive confirmations.
HTML
<button class="btn btn--primary" type="button">Send invitations</button>
<button class="btn" type="button">Preview</button>
<button class="btn btn--ghost" type="button">Edit</button>
<button class="btn btn--link" type="button">Copy link</button>
<button class="btn btn--danger" type="button">Delete event</button>

Toggle and disclosure

aria-pressed for a toggle; aria-expanded + aria-controls for a disclosure such as the CMS block “Collapse”.
HTML
<div class="cluster" role="group" aria-label="Filter by reply">
<button class="btn btn--sm" type="button" aria-pressed="false">All</button>
<button class="btn btn--sm" type="button" aria-pressed="true">Waiting</button>
<button class="btn btn--sm btn--ghost" type="button" aria-expanded="true" aria-controls="blk">Collapse</button></div>

Sizes

Medium is the default. Small lives in table rows, card headers, toolbars and the CMS block controls; large is for auth and public pages where the button is the point of the page.

Heights --control-height-sm/md/lg; padding --space-3/4/6; font --font-size-sm/md/lg.
HTML
<button class="btn btn--primary btn--sm" type="button">Small · 32px</button>
<button class="btn btn--primary" type="button">Medium · 40px</button>
<button class="btn btn--primary btn--lg" type="button">Large · 48px</button>

Both themes

  • Loading keeps the button's width and label, shows a spinner over it, sets aria-busy="true" and ignores further clicks. Do not add disabled: focus must stay on the button that was pressed.
  • Disabled uses the native attribute; it is not focusable and is 50% opaque. Prefer an enabled button that explains the problem on activation, as the delete dialog does until the event name is typed.
  • Pressed (aria-pressed="true") uses the accent-subtle look, the same as a selected chip.

Responsive behaviour

  • Below 48rem (--layout-breakpoint-md) the primary action in a page header becomes full width; secondary actions sit beneath it.
  • In dialog footers buttons stay on one row and wrap when narrower than their combined width; the primary stays last (rightmost, or bottom when wrapped).
  • On the public RSVP form, “Send my RSVP” and “Can’t make it?” sit at opposite ends (.form-actions--between); at 360px they wrap with the primary on its own row.
  • Medium and large buttons are 40 and 48px tall; small (32px) appears only inside rows that are themselves targets, with 8px between neighbours.
  • Labels never truncate; a label that wraps at 360px is too long. Shorten the verb phrase.

Theming

The button reads only semantic tokens, mapped into component tokens (--btn-bg, --btn-fg, --btn-border, --btn-bg-hover, --btn-bg-active, --btn-height, --btn-padding) that each variant and size overrides. A theme changes semantic tokens; a re-skin overrides component tokens; neither edits .btn.

/* A partner theme with a different primary, without touching .btn */
[data-theme="partner"] .btn--primary { --btn-bg: var(--color-accent); --btn-fg: var(--color-fg-on-accent); }

In dark the accent lightens to --palette-blue-300 and the label flips to --color-fg-on-accent (blue-950) so the pair stays above 7:1; the danger button does the same on the red ramp.

Accessibility

Role and pattern

Native <button type="button">, or type="submit" inside a form. A button that navigates is an <a href> with the button classes, as in “New event”. Toggle buttons follow the APG Button pattern with aria-pressed.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order.
Enter, SpaceActivates. Space fires on key up, so a mis-press can be cancelled by moving away.
EscNo effect on the button; inside a dialog it closes the dialog instead.

Focus

The shared ring (2px --color-focus-ring, 2px offset) shows on :focus-visible only. On a primary button the offset gap shows the surface, which keeps the ring 3:1 against both the button and the page. When a busy button finishes, focus stays on it.

Labelling

The visible label is the accessible name. Icon-only buttons set aria-label with the verb and the object (“Remove guest Jonah Adeyemi”, “Move hero down”) and show a tooltip. Busy buttons keep their name and add aria-busy="true"; the outcome is announced by the toast region.

Motion

Background and border transition over --duration-fast; active translates 1px. Reduced motion zeroes the durations through the tokens. The busy spinner keeps turning, three times slower, because it is a status indicator.

Touch

Medium (40px) and large (48px) meet the 24px minimum; the comfortable 44px target is met by large buttons and by small buttons whose whole row is tappable. Icon-only small buttons in table rows keep 8px between neighbours.

Content

  • Verb phrases in sentence case: “Send my RSVP”, “Schedule invitations”, “Add guest”. Never “OK”, “Submit” or “Click here”.
  • Name the object when context does not: “Remove 3 guests” in the remove dialog, “Remove” in a row.
  • Destructive labels name the loss: “Delete event”, “Reset all links”, not “Confirm”.
  • Three words or fewer where possible.
  • The label does not change while busy; progress text lives in the toast or a live region.

Drift fixed during extraction: all 18 busy buttons in the mocks set disabled together with aria-busy and swapped the label for “Saving…”, “Deleting…” and so on. disabled drops keyboard focus and halves the opacity, and the swapped label is hidden by the spinner anyway. The system keeps the original label, sets only aria-busy="true" (CSS blocks further clicks) and announces progress through the toast region. The spinner now hides an icon as well as the label, and pressed buttons gained the accent-subtle look so they match pressed chips.
