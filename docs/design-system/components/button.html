Button

Buttons start an action: save a guest, schedule invitations, publish the page. One primary button per view says what matters most.

Overview

Use a button when activating it changes something: it submits, saves, deletes, opens a dialog or starts a job. Use a Link when it only goes somewhere (the mocks render navigation actions such as “Add guest” as <a class="btn">; that is allowed: same look, link semantics). Use IconButton when there is no room for a label.

  • Primary: the one action the view exists for (“Save guest”, “Send my RSVP”, “Publish”). Never two per view.
  • Secondary (default look): every other action that still deserves a box (“View public page”, “Try again”).
  • Ghost: dense surfaces: table rows, card headers, dialog Cancel, toolbar actions (757 uses in the mocks).
  • Link: low-emphasis action inside a sentence or alert.
  • Danger: destructive confirmation only (“Delete event”, “Remove 2 guests”, “Remove block”), after or inside a confirmation step.

Anatomy

  1. Leading icon (optional)1.25em, inherits the label colour, aria-hidden.
  2. LabelVerb phrase in sentence case; it is the accessible name.
  3. ContainerHeight --control-height-*, --radius-md, 1px border, padding --space-3/4/6.

Variants

Primary, secondary, ghost, link, danger — emphasis from highest to lowest.
HTML
<button class="btn btn--primary" type="button">Save guest</button>

<button class="btn btn--ghost" type="button">Edit</button>
<button class="btn btn--link" type="button">Change</button>
<button class="btn btn--danger" type="button">Delete event</button>

With icons, block

Leading icons clarify the verb; block fills its container (sign-in, RSVP on phones).

Sizes

sm: table rows, card headers, alerts. md: default. lg: auth and guest hero actions. Coarse pointers raise every size to 44px.

Both themes

  • Loading keeps the width, hides the label behind a spinner, sets aria-busy="true" and ignores clicks (mocks: Saving, Sending states).
  • Disabled uses the native attribute and 50% opacity. Prefer an enabled button that explains the problem on press (mocks keep “Save guest” enabled in the invalid state).
  • Pressed (aria-pressed) and expanded (aria-expanded, block editor “Collapse/Edit”) keep the same look; the attribute carries the state.

Responsive behaviour

  • Below MD (768px) the page-header actions wrap under the title and the primary action becomes full width.
  • Dialog footers keep Cancel then the primary action on one row; when they wrap, the primary stays last.
  • Labels never truncate; a label that wraps at 360px is too long.
  • Under (pointer: coarse) the hit area grows to --target-comfortable (44 × 44 px, L2-084); fine pointers keep the visual size, never below --target-min (24 px).

Theming

Reads component tokens --btn-bg, --btn-fg, --btn-border, --btn-bg-hover, --btn-bg-active, which each variant maps to semantic tokens. In dark theme the accent lightens to --palette-blue-300 and the label flips to --color-fg-on-accent (blue-950); danger does the same on the red ramp.

Accessibility

Role and pattern

Native <button type="button"> (or type="submit" in a form). Navigation actions are <a href> with the same classes. No ARIA role. APG Button.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order.
Enter, SpaceActivates. Links activate with Enter only.
EscNo effect; inside a dialog it closes the dialog unless a request is in progress.

Focus

Shared ring: --focus-ring-width (2px) --color-focus-ring with 2px offset on :focus-visible, ≥ 3:1 on every surface (L2-086).

Labelling

Visible label is the name. When a button repeats per row (“Edit”, “Remove”) the name must still start with the visible text and add the object in visually hidden text: “Edit Jonah Adeyemi”. Loading keeps the name and adds aria-busy; progress text goes to the page live region.

Motion

Background and border transition over --duration-fast; active nudges 1px. Reduced motion zeroes the durations; the loading spinner keeps turning (status, not decoration).

Touch

md 40px and lg 48px; sm 32px only inside rows and headers. Under (pointer: coarse) the hit area grows to --target-comfortable (44 × 44 px, L2-084); fine pointers keep the visual size, never below --target-min (24 px).

Content

  • Verb phrases in sentence case: “Save guest”, “Schedule invitations”, “Send my RSVP”. Never “OK”, “Submit”, “Yes”.
  • Destructive labels name the loss: “Delete event”, “Remove 2 guests”, “Reset links”.
  • Guest-facing copy is warm but plain: “Send my RSVP”, “Can’t make it?”.
  • Keep to three words where possible.
