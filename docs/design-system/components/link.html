Link

Links take people somewhere: back to sign in, to a guest list, to a field that needs fixing. They are always underlined, so they never depend on colour to be found.

WCAG 2.2 AAStatus: stableNative <a href>

Overview

Use a link when activating it navigates: to another page, to a section, to a file, or to a field from the error summary. If it changes something (saves, sends, deletes, opens a dialog in place) it is a button. A link may look like a button when it is the main way forward, as “New event” and “View public page” do in the mocks; it stays an <a href>.

  • Inline sits in a sentence and takes the text’s size.
  • Standalone stands on its own line or in a cluster (“Forgot password?”, “Back to sign in”) and uses the label weight with a 24px target.
  • With icon adds a leading icon that says what happens (download).
  • External opens another site in a new tab and says so, visually and to screen readers. The mocks have none yet; maps and calendar links on the public page are the expected first uses.
  • Quiet inherits the surrounding colour; for links inside alerts, the footer and breadcrumbs, where the link colour would clash with the tone.

Anatomy

  1. Icon (optional)1em, currentColor, aria-hidden.
  2. LabelSays where it goes; --color-fg-link.
  3. Underline1px, offset 0.15em; 2px on hover. Always present.

Sizes

Links take the size of the text around them; standalone links use the label size, 14px.

States

Hover, focus and active are forced here with data-state. Visited links look the same as unvisited ones on purpose: Invitely is an app, not a reading site, and a purple “Guests” link tells nobody anything. Links have no disabled state; remove a link that cannot be followed and explain why in text.

Responsive behaviour

  • Inline links wrap with their sentence. Long URLs are never the link text, so nothing overflows at 360px.
  • Standalone links keep a 24px minimum height, 44px on touch screens (L2-084); in a .cluster--between (“Keep me signed in” and “Forgot password?”) they wrap onto their own line when the row is too narrow.
  • (hover: none) devices see the same underline; nothing about a link depends on hover.

Theming

Links read --color-fg-link and --color-fg-link-hover: blue-700/800 in light and blue-300/200 in dark, both above 4.5:1 on canvas, surface and raised surfaces. Quiet links take currentColor so they match any alert tone. There are no component tokens; a theme changes the two semantic ones.

Accessibility

Role and pattern

Native <a href>; never a <span> with a click handler, and never an <a> without href. See the APG Link pattern.

Keyboard

KeyAction
Tab / Shift+TabMoves between links.
EnterFollows the link (Space scrolls the page, unlike a button).
Ctrl+Enter / middle clickOpens in a new tab, which is why navigation must be a real link.

Focus

The shared 2px ring with 2px offset and a small radius around the text. Error-summary links move focus to the field they name.

Labelling

The link text makes sense on its own (WCAG 2.4.4): “Download the CSV template”, not “Click here”. External links add visually hidden “(opens in a new tab)” after the visible icon. Icons are aria-hidden.

Motion

None; underline thickness changes instantly on hover.

Touch

Standalone links have a 24px minimum height, raised to 44px under (pointer: coarse) (L2-084); inline links in a sentence use the WCAG 2.5.8 inline exception.

Content

  • Say where it goes or what you get: “Back to sign in”, “Download the CSV template”, “Review guests”.
  • Sentence case, no full stop on standalone links; inline links are part of the sentence’s punctuation.
  • Questions are fine as standalone links when they match what people ask: “Forgot password?”.
  • Error-summary links repeat the field error: “Choose a meal for each guest.”
  • Never “click here”, “read more” or a bare URL.
