Select

A select picks one value from a short list everyone already understands: event type, meal, party size, time zone. It is the browser’s own control, styled to match the fields around it.

WCAG 2.2 AAStatus: stableNative <select>

Overview

Use a select when there is exactly one answer from a fixed list of about 4 to 15 options and the options do not need to be compared side by side. With five or fewer options that people should see before choosing (attending or not, send now or later) use a radio group. For free text use a text field.

  • In the mocks: event type, meal and party size on the RSVP form, guest group and places in the guest dialog, “Sort by” above the events table, and time zone on the new-event form and in account settings.
  • The system uses the native <select> only. A custom listbox is not part of the system; add one (APG Listbox) only when a need appears that native cannot meet, such as searching hundreds of options.
  • Changing a select never navigates or saves by itself (WCAG 3.2.2). “Sort by” re-sorts the table in place, which is not a change of context.

Anatomy

  1. LabelFrom the form field; always visible, including “Sort by”.
  2. ValueThe selected option in --text-body; same box, border and radius as the text field.
  3. ChevronDrawn with two gradients in currentColor, 40px right padding keeps long values clear of it.

Variants

Two variants: a select with a sensible default, and one with a placeholder option when no default would be honest.

Your invitation allows up to 2 places.
Choose a meal for each guest.
Default value when one is right for most people (event type, party size); a disabled-looking placeholder option, value="" and required when the person must actively choose (meal).

Sizes

Medium is used everywhere in the mocks. Small fits a filter bar or table toolbar; large pairs with large text fields.

.select--sm / default / .select--lg map to --control-height-sm/md/lg.

States

Hover and focus forced with data-state; invalid and disabled use the real attributes. A select has no read-only state; show the value as text instead.

Responsive behaviour

  • Full width of its column. In the events filter bar “Sort by” sits after search and the filter chips in a wrapping row, so on phones it drops onto its own line at full width.
  • Short related selects (event type and time zone) may share a .form-row from 48rem.
  • Phones open the platform picker (wheel on iOS, sheet on Android), which is why the system stays native.

Theming

Reads the same component tokens as the text field (--field-bg, --field-border, --field-border-hover, --field-height). The chevron uses currentColor, so it follows the text colour in both themes. color-scheme on the theme makes the open option list dark in the dark theme.

Accessibility

Role and pattern

Native <select> with <label for>; the browser exposes it as a combobox or listbox with the right semantics. No ARIA added.

Keyboard

KeyAction
TabFocuses the select.
↑ / ↓Changes the value (closed, on Windows) or moves through options (open).
Alt+↓, Space or EnterOpens the option list, depending on platform.
TypingJumps to the first option starting with the typed letters.
EscCloses the list without changing the value.

Focus

Same flush ring and border as the text field.

Labelling

Visible label; help and error in aria-describedby; required on selects with a placeholder option so “required” is announced and the empty value fails validation.

Motion

Border transitions over --duration-fast; the option list is the platform’s and does not animate from the system.

Touch

40px tall with a fine pointer and at least 44px under (pointer: coarse) (L2-084), full width, opens the native picker.

Content

  • Label names the choice: “Meal”, “Event type”, “Time zone”, “Sort by”.
  • Options are short, parallel and in a logical order (time zones by offset, meals as the venue lists them); no “Please select”.
  • Placeholder options say the action: “Choose a meal”. They are never a real answer.
  • Time zones name a city people know: “Pacific Time (Vancouver)”.
