Alert

An alert sits in the page and explains a state that persists until something changes: invites are closed, two emails bounced, the block wasn’t added. A banner is the same component spanning the top of the page.

Overview

Use an alert when the message is about the content in front of the person and must stay visible until it is resolved or no longer true. Use a toast to confirm an action that just happened, an inline message for one field, and an empty state when a whole region failed to load.

  • Inline alert sits inside a card, dialog or form: “Recent responses didn’t load”, “The block wasn’t added”.
  • Banner (.banner) spans the top of a page and describes the page’s state: the event schedule (“Invites are open.”) or the public page (“RSVP closes in 19 days.”).
  • Error summary (.form-summary) heads a form after a failed submit and links each problem to its field. See Forms.

Anatomy

  1. Tone edge4px left border in --alert-border.
  2. IconTone icon, 20px, --alert-icon, aria-hidden.
  3. TitleThe state in a few words, --text-label.
  4. TextConsequence and what to do, one or two sentences.
  5. Actions (optional)Small buttons or links; at most two.
  6. Dismiss (optional)Only for alerts whose state the person can ignore.

Variants

Four tones

Info states a fact, success confirms a lasting result, warning needs attention soon, danger means something failed or is blocked. Tone is carried by icon, edge and title together.

  • Dismissed alerts are removed from the DOM and remembered per event, so “Invites are open.” does not return on every visit. Danger and persistent warnings (“Your public page isn’t published yet.”) are not dismissible.
  • Retrying: the Try again button goes busy (aria-busy); on success the alert is removed and the content it replaced appears.

Responsive behaviour

  • The icon stays top-left; title, text and actions stack in one column at every width.
  • Actions wrap onto a second line on phones (.alert__actions wraps) rather than pushing the page wider.
  • Banners keep their content centred and wrap the text and actions onto separate lines below 40rem.
  • The dismiss button keeps a 24px target at every width.

Theming

Each tone sets four component tokens, --alert-bg, --alert-fg, --alert-border and --alert-icon, from the matching --color-{tone}-* semantic tokens. In dark the backgrounds become deep tints (950 steps) and the text and icons pale 200/300 steps, so every pair stays above 4.5:1.

/* A quieter info alert for a partner theme */
[data-theme="partner"] .alert { --alert-bg: var(--color-bg-surface-sunken); }

Accessibility

Role and pattern

Follows the APG Alert pattern only when the content is new and important: a failed action (“Nothing was deleted”) or the error summary use role="alert". Alerts present when the page loads, and banners describing a page’s state, use role="status", so they are not shouted on every visit.

Keyboard

KeyAction
TabReaches the alert’s actions and dismiss button in DOM order; the alert itself is not focusable.
Enter, SpaceActivates an action or Dismiss.
Tab after submitThe error summary takes focus first; each link moves focus to its field.

Focus

Alerts never take focus, except the error summary, which is focused when it appears so the screen reader reads it and the next Tab reaches the first link. Dismissing moves focus to the next focusable element after the alert.

Labelling

The title and text are the content; the icon is aria-hidden and the tone is in the words (“didn’t”, “failed”, “closed”). The dismiss button names the alert (“Dismiss: Invitations sent to 84 people.”).

Motion

Alerts appear without animation, so a layout shift is never mistaken for movement; dismissing removes them immediately.

Touch

Actions are small buttons (32px) inside a block that is not itself a target; they keep 12px between them. Dismiss is 24×24px.

Content

  • Title: the state, not the event that caused it: “Invites are closed”, “2 invitation emails bounced”, “Nothing was deleted”.
  • Text: the consequence and the next step: “Check the addresses in Guests. Resend to those two people once fixed.”
  • Failures reassure first: say what is unchanged (“Your event and its 84 invitees are unchanged”).
  • Error summary title counts the problems: “1 thing to fix”, “2 things to fix”; each item is the field’s own error message.
  • Sentence case; full stops on banners are optional but consistent within a page.
