Switch

A switch turns a setting on or off the moment it is flipped, like the organiser's notification preferences. If nothing happens until a Save button, it is a checkbox, not a switch.

WCAG 2.2 AAStatus: stablerole="switch" on a checkbox

Overview

Use a switch for a single binary setting with an immediate effect, confirmed in place (“Saved”). Use a checkbox when the choice is part of a form that is submitted, and a radio group when the two states need their own words.

  • Label right (default): the switch leads, the label follows; for short lists in a form-like column.
  • Label left (.switch--end): the label fills the row and the switch sits at the end; for settings lists such as the account Notifications card.
  • With description (.switch__text): a muted second line explains what “on” does.

Anatomy

  1. Track44 × 24px, --radius-full; off is --color-border-strong, on is --color-accent.
  2. Thumb20px circle in --color-bg-surface with --shadow-1; slides over --duration-base.
  3. LabelNames the setting, not the action.
  4. Description (optional)<small> in --color-fg-muted.

Sizes

Switches have one size: a 44 × 24px track, which already meets the comfortable target width. Override --switch-width, --switch-height and --switch-thumb together in a theme if needed.

States

Pointer and focus states are forced with data-state; the value is the real checked attribute.

ValueDefaultHoverFocusDisabled
Off
On

Both themes

  • Hover darkens the off track to --color-fg-muted and the on track to --color-accent-hover.
  • Disabled halves the opacity and greys the label; say why nearby (“Daily summaries need a verified email”).
  • Saving: the switch flips at once; the inline status beside the group says “Saving…” then “Saved”. If the save fails, the switch flips back and an error toast explains why.
  • There is no invalid state: a switch cannot be wrong, only unavailable.

Responsive behaviour

  • Label-left switches fill the row at every width, so the switch lines up at the right edge of the card even when labels wrap at 360px.
  • The label is part of the target, so on phones the whole row toggles the setting.
  • Never place two switches on one row.

Theming

The switch reads --color-border-strong (off track), --color-accent (on track), --color-bg-surface (thumb) and --shadow-1, with component tokens --switch-width, --switch-height and --switch-thumb.

[data-theme="kiosk"] .switch { --switch-width: 3.5rem; --switch-height: 2rem; --switch-thumb: 1.75rem; }

In dark the off track is gray-450 on a gray-900 card and the thumb is gray-900, so the thumb reads as a dark notch on the blue-300 on-track; the pair is checked below in both themes.

Accessibility

Role and pattern

A native checkbox with role="switch" inside its label, following the APG Switch pattern. Screen readers announce “Email me when someone replies, switch, on”.

Keyboard

KeyAction
Tab / Shift+TabMoves to and from the switch.
SpaceToggles on and off.
EnterDoes not toggle; it submits a surrounding form if there is one, so avoid switches inside submit forms.

Focus

The shared 2px ring with a 2px offset surrounds the track on :focus-visible. Focus stays on the switch while it saves.

Labelling

The label describes the setting so “on” reads naturally: “Email me when someone replies”. The result of a save is announced by the role="status" line, not by changing the label.

Motion

The thumb slides and the track recolours over --duration-base with --ease-standard; under reduced motion it jumps.

Touch

The track is 44px wide and the whole label row is tappable; rows are at least 24px tall and settings cards space them by --space-4.

Content

  • Name the setting as a statement that is true when on: “Send me a daily summary”, not “Daily summary: on/off”.
  • Do not add “on” and “off” text beside the track; the state is in the control.
  • Descriptions give the concrete effect: “One email on Wed 4 Nov”.
  • Confirm with a short status: “Saved”, or “Couldn’t save. Try again.”
