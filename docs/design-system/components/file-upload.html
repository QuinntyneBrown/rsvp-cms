File upload

File upload brings a guest list in from a spreadsheet. A drop zone takes a dragged file; a button opens the file picker; a file list shows what is happening to the file.

WCAG 2.2 AAStatus: stableNative <input type="file">

Overview

Use file upload where a file is the natural input; in Invitely that is the guest CSV on the import page. For one or two guests use the add guest dialog, never an upload.

  • Drop zone (.dropzone): a dashed area with an icon, one sentence and the file button. Dropping is an enhancement; the button is the control.
  • File button (.file-trigger): a <label> styled as a button around a visually hidden <input type="file">, so it works with keyboard and screen readers.
  • File list (.file-list): one row per file with name, status and a progress bar while it is read or imported.

Anatomy

  1. Icon48px circle in --color-accent-subtle; aria-hidden.
  2. InstructionOne sentence in --color-fg-muted, 36ch maximum.
  3. File buttonPrimary button wrapping the hidden file input; the accessible control.
  4. Container1px dashed --color-border-strong, --radius-lg, padding --space-8 × --space-4.

Responsive behaviour

  • The drop zone fills its card at every width; text centres and wraps to 36ch.
  • Phones rarely support drag and drop, so the button is always visible and is the main path; the instruction still reads well without dragging.
  • File rows keep the name and status on the left and the cancel/remove button on the right; the progress bar runs under both.

Theming

The drop zone reads --color-bg-surface, --color-border-strong through --dropzone-border, and --color-accent-subtle / --color-fg-accent for the icon. Dragging and failed override --dropzone-border only.

.dropzone[data-state="dragging"] { --dropzone-border: var(--color-accent); }

In dark the icon circle becomes blue-950 with a blue-300 glyph, and the dragging fill uses the same deep tint, so the zone brightens at its edge rather than turning into a bright slab.

Accessibility

Role and pattern

The control is a native <input type="file" accept=".csv">, visually hidden inside a <label> that looks like a button. The drop zone is not focusable and has no role; it only listens for drag events. Progress rows use role="progressbar".

Keyboard

KeyAction
TabReaches the file input; the ring is drawn on its label button.
Enter / SpaceOpens the system file picker.
TabFrom a file row, reaches its Cancel or Remove button.

Focus

The hidden input takes focus and the label draws the shared ring through :has(input:focus-visible). After a file is chosen focus stays on the button; after Remove, focus returns to the button.

Labelling

The input is named by the button text, “Choose CSV file”. Row buttons name the file: “Cancel reading guests.csv”, “Remove guests.csv”. Status changes (read, failed, imported) are announced by the page's role="status" or role="alert" region, as on the import page.

Motion

The zone's border and fill change over --duration-fast; the indeterminate bar loops over --duration-shimmer and becomes a static 60% bar under reduced motion.

Touch

The file button is 40px tall; row buttons are 32px with the whole row around them. Dragging is never required (WCAG 2.5.7): the button does everything the drop does.

Content

  • Instruction: “Drop a CSV file here, or choose one from your computer.” Name the file type.
  • Button: “Choose CSV file”, not “Browse” or “Upload”.
  • Say what the file needs before the upload: “Columns: name, email, group, plus-ones. Headers can be in any order.”
  • Errors name the problem and the fix: “It has no email or name column. Add one and upload again.”
  • Progress counts real things: “49 of 81 added”, “Reading… 84 rows so far”.
