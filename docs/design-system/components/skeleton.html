Skeleton

A skeleton draws grey shapes where content is about to appear, so the page keeps its layout and the person can see what is coming. Every Invitely page has a loading state built from them.

WCAG 2.2 AAStatus: stablearia-busy="true"

Overview

Use skeletons for the first load of a page or region whose layout you know: the guest list, the dashboard, the RSVP form. Use a spinner for a short refresh of something already on screen, and a progress bar for measurable work. Show skeletons only for the parts that load; the shell, breadcrumb, page header and tabs render immediately.

Anatomy

  1. Title.skeleton--title: 1.5em tall, 40% wide.
  2. Circle.skeleton--circle: avatar placeholder, 40px.
  3. Text lines.skeleton--text: one per line; the last line of a group is 60% wide.
  4. Control.skeleton--control: a form field or table row, --control-height-md tall.

Sizes

Shapes take their size from the content they replace: text from the font size (em), controls from --control-height-md, circles from the avatar size.

Both themes

  • Loading: a light band sweeps left to right every --duration-shimmer.
  • Reduced motion: the sweep stops and the shapes stay as flat --color-bg-subtle blocks.
  • Loaded: the real content replaces the skeleton in one swap, and aria-busy is removed. Never mix half-loaded content and skeletons in one region.
  • Slow: after 10 seconds, replace the skeleton with the region’s error state (“We couldn’t load…”), not an endless shimmer.

Responsive behaviour

  • Skeletons live inside the same layout as the content, so they reflow with it: one column on phones, the page grid above.
  • Use the same number of rows the page shows at that width (about 6 table rows on a phone, 10 on desktop).

Theming

Shapes use --color-bg-subtle with a --color-bg-subtle-hover sweep, which reads as a recessed surface in both themes. Radius follows the content: --radius-sm for text, --radius-md for controls, full for circles.

Accessibility

Role and pattern

Skeleton shapes are empty and decorative. The region that holds them has aria-busy="true" and a name (aria-labelledby pointing at visually hidden text such as “Loading guests”), so a screen reader hears one message instead of a run of empty shapes.

Keyboard

KeyAction
TabSkips the region entirely; nothing inside is focusable until the content loads.

Focus

Loading never moves focus. If focus was on a control in the region before a reload, it returns to the matching control afterwards.

Labelling

One hidden label per busy region, naming the content: “Loading guests”, “Loading account”.

Contrast

Skeletons are exempt from contrast requirements (no information); they still use tokens so they track the theme.

Motion

The shimmer is the only motion and stops under reduced motion.

Touch

Not interactive.

Content

  • The hidden label is “Loading” plus the region’s name, matching the page title: “Loading guests”.
  • No visible “Loading…” text next to skeletons; the shapes already say it.
