Error page

When a whole page cannot be shown, Invitely keeps the top bar, says what happened in one plain sentence and offers one way back.

WCAG 2.2 AAStatus: stable

Overview

An error page is an empty state placed in a reduced shell: the top bar with the brand (organiser pages) or the event name (guest pages), and the message centred in the remaining height. Use it only when the page as a whole has no content to show; when one region fails, use the region’s error empty state and keep the rest of the page.

PageWhenPrimary action
404 Not foundThe route or record does not exist.Go to dashboard
403 ForbiddenSigned in, but not an organiser or co-host of this event.Back to dashboard
500 Server errorThe server failed; includes a reference id for support.Try again
OfflineNo connection.Retry connection
Invalid / expired invitationA guest’s code or link does not match, or RSVPs have closed.Enter an invitation code

Anatomy

  1. Reduced shellTop bar with the brand only; no navigation, search or account (they may be the thing that failed).
  2. IconSearch for not found, lock for forbidden, warning for server error, wifi-off for offline.
  3. TitleWhat happened, in the person’s terms; the page’s <h1>.
  4. TextWhy, and what is safe.
  5. Reference (500 only).error-page__code, monospace, copyable.
  6. ActionsOne way forward, one way back.

Responsive behaviour

  • Content centres in the space below the top bar (min-height: calc(100dvh - var(--layout-topbar-height))), so the page never scrolls just because of the bar.
  • Actions wrap, primary first, on phones.
  • The reference id wraps rather than overflowing.

Theming

Same tokens as Empty state: accent circle by default, .empty--error for 500, .empty--neutral for 403 and offline, where nothing is broken.

Accessibility

Role and pattern

A normal page: skip link, <header>, <main>, one <h1> (the title), and a <title> that starts with the problem (“Page not found — Invitely”) so it is announced on load. The server should also return the matching HTTP status.

Keyboard

KeyAction
TabSkip link, brand, then the actions.
EnterActivates.

Focus

Focus starts at the top of the document like any page load; nothing is auto-focused.

Labelling

Link and button text works alone (“Back to dashboard”). The reference id is plain text so it can be selected and read.

Content

  • Say what happened without blame or codes: “We can’t find that page”, not “404 error”.
  • Reassure about data on 500 and offline: “Your changes are saved up to the last successful step.”
  • Name who can help on 403 and invalid invitations: “Ask Priya Natarajan…”.
  • Only promise what the page shows: the offline page must not refer to data “shown below” unless it is shown.
