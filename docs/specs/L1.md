# L1 - High-Level Requirements

## L1-001: Organiser accounts and sign-in
Organisers must be able to create an account, sign in, recover a forgotten password and sign out. Only signed-in organisers can manage events.

## L1-002: Event setup and lifecycle
Organisers must be able to create an event (for example a birthday, holiday, anniversary or other occasion), edit its details, set the window in which guests can reply, see whether invitations are open or closed, regenerate invitation links and delete the event.

## L1-003: Event public page
Organisers must be able to build the public event page that guests see from a set of content blocks (hero, details, schedule, map, RSVP form, FAQ, photo gallery and gift list). Organisers must be able to add, reorder, edit and remove blocks, keep unpublished changes as a draft, preview the page as a guest sees it, and publish or discard changes.

## L1-004: Guest list management
Organisers must be able to maintain the list of invitees for each event: add, edit, search, filter, select, remove and export guests, and import a guest list from a CSV file with validation before anything is saved.

## L1-005: Invitation delivery and reminders
Organisers must be able to schedule invitation emails to all invitees or only to invitees who have not replied, preview the email, track which emails are scheduled, sent or bounced, and send reminders that stop for any guest who has already replied. Each guest must receive a personal invitation link.

## L1-006: Guest invitation access and RSVP
Guests must be able to open their invitation with a personal link or an invitation code, read the public event page, reply yes or no, state party size, meal choice, dietary needs, a song request and a message, change their reply until the invite window closes, and decline with a message. Guests must never see another guest's data.

## L1-007: Response review
Organisers must be able to review every guest reply for an event, see totals (attending, guests coming, meal counts, dietary counts), search and filter replies by status, and export replies.

## L1-008: Organiser dashboard and event overview
Organisers must be able to see a dashboard summarising invitees, attendance, waiting replies and scheduled emails across their events, a list of upcoming events, and an overview page per event with its status, invite window, reply progress and latest replies.

## L1-009: Notifications
Organisers must be able to see in-app notifications for guest replies, email bounces, reminders that are due and attendance milestones, and mark them as read.

## L1-010: Account settings
Organisers must be able to edit their profile and notification preferences, and change their password.

## L1-013: Performance and scalability (cross-cutting)
The public RSVP page and organiser screens must load quickly, lists and bulk operations must stay responsive at the volumes stated in the L2 requirements, and the application must scale horizontally by adding stateless instances.

## L1-014: Responsive design (cross-cutting)
Every screen and dialog must work at extra small (under 576px), small (576px and up), medium (768px and up), large (992px and up) and extra large (1200px and up) viewport widths, with no horizontal page scrolling and touch-friendly controls.

## L1-015: Accessibility (cross-cutting)
Every screen must meet WCAG 2.2 Level AA: sufficient contrast in light and dark themes, full keyboard operation with visible focus, labelled form controls, announced errors, and respect for reduced-motion preferences.

## L1-018: Privacy and personal data (cross-cutting)
Guest names, email addresses, meal choices and dietary or allergy information are personal data. The system must limit who can see it, keep it only as long as needed, erase it when an event is deleted.
